# Official Google Cloud Well-Architected Framework (`WAF`) — 6 Pillars + AI & ML Perspective

Canonical Public Sources:
- Framework Overview: https://docs.cloud.google.com/architecture/framework
- AI & ML Perspective: https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml

## Pillar Checklist & Public Documentation Map

| Pillar | Core Principles & AI/ML Validation Checks | Verified Public URL |
| :--- | :--- | :--- |
| **1. Security, Privacy & Compliance** | • **Least-Privilege Identity & Zero Keys:** Dedicated Cloud Run service account (no `roles/editor`/`owner`, zero downloadable JSON keys); restrict Cloud Run ingress with `--no-allow-unauthenticated` and explicit `roles/run.invoker` for Discovery Engine SA.<br>• **Data Minimization & Residency:** Tokenize PII upstream (`STU-XXXX`); pin storage, Cloud Run, and Model Armor to `europe-west2` (London).<br>• **AI Guardrail Base State:** Screen prompts, untrusted tool data, and responses with regional **Model Armor** (`https://docs.cloud.google.com/model-armor/data-residency`). | https://docs.cloud.google.com/architecture/framework/security<br>https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml |
| **2. Reliability** | • **Regional Failure Domain:** Use regional serverless services (`Cloud Run` in `europe-west2`, multi-zone automatic failover) and regional `BigQuery` datasets rather than single-zone VMs.<br>• **Idempotent Re-Runs & Graceful Degradation:** Deterministic matcher must run even if Gemini explanation API experiences transient `429`/`503` errors; HITL staging queue prevents partial/corrupt ERP writes.<br>• **Automated Circuit Breaker:** Stage 3 autonomy must auto-revert to Stage 2 HITL on elevated override rates or policy breach alerts. | https://docs.cloud.google.com/architecture/framework/reliability |
| **3. Cost Optimization (`FinOps`)** | • **Model Right-Sizing:** Route structured orchestration and concise explanations to `gemini-2.5-flash` rather than frontier reasoning models.<br>• **Eliminate Token Loops:** Never call LLMs per row on `1,000+` tabular records; run matching math in Python (`$0` token spend) and invoke Gemini only on summary/chat turns.<br>• **Scale-to-Zero & Quota Caps:** Set `--min-instances=0 --max-instances=2`, enforce `max_output_tokens`, and govern shared token pools (`$15/seat/mo` GE dev quota; Apigee `LLMTokenQuota` at enterprise scale). | https://docs.cloud.google.com/architecture/framework/cost-optimization |
| **4. Operational Excellence** | • **Evaluation-Driven Promotion:** Gate releases with automated `pytest` (100% deterministic rule invariants) + `adk eval` / Vertex AI Gen AI Evaluation (`>=0.95` tool trajectory, `>=0.98` groundedness) before Cloud Run / Gemini Enterprise promotion.<br>• **Auditability & Continuous Learning:** Log `{run_id, rule_version, agent_choice, human_override, reason}` to `transfer_audit_log` so Stage 1 human edits automatically expand the Golden Eval Set.<br>• **Governed Release Handover:** Package `Dockerfile`, `.env.example`, eval scorecard, and IAM script in `IT_HANDOVER_BUNDLE/` for IT `discoveryengine.admin` deployment. | https://docs.cloud.google.com/architecture/framework/operational-excellence<br>https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/evaluation-agents |
| **5. Performance Optimization** | • **Algorithmic Separation:** In-memory/vectorized Python 3-pass matching across `1,050` students and `470` stores completes in `<1s` (`<3s` end-to-end vs hours of manual 30-row Sheet copy-pasting).<br>• **Low-Latency Chat:** Keep tool payloads compact (filtered store/student slices, never dumping full 1,050-row CSVs into the LLM context window). | https://docs.cloud.google.com/architecture/framework/performance-optimization |
| **6. Sustainability** | • **Carbon-Efficient Compute & Inference:** `europe-west2` (London) regional serverless scale-to-zero + `gemini-2.5-flash` + Python-first matching minimizes idle compute and unnecessary GPU/TPU inference cycles. | https://docs.cloud.google.com/architecture/framework/sustainability |
