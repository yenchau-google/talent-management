# NEXT PLC — Google Cloud Well-Architected & FinOps Review (`03-waf-review.md`)

## 1. Workload Profile & Architectural Context (Phase 2 Medallion & Enterprise UX Architecture)
- **Workload Pattern:** Seasonal/bursty retail HR transfer matching (`1,050` student colleagues $\times$ `470` UK stores during Summer/Christmas windows) backed by a **Two-Dataset Google Cloud BigQuery Medallion Architecture (`next_student_transfer_staging` and `next_student_transfer_gold` in `europe-west2`)** and **Dataplex Auto Data Quality (`next-student-transfer-dq-scan`)**.
- **Two-Service Compute Topology (`europe-west2`):**
  1. **Cloud Run App 1 (`next-portal-intake-app`):** Student (`STU-XXXX`) & Store Manager (`SM-XXX`) Self-Service Portal (`src/portal_server.py` + `ui/portal_intake.html`), protected by **Cloud Run native IAP (`--iap`)**.
  2. **Cloud Run App 2 (`next-student-transfer-agent`):** Pure Headless HR Multi-Agent A2A Backend (`src/server.py` + `src/agent.py`) registered onto **Gemini Enterprise (`gemini-enterprise-retail-app`)**, deployed with `--no-allow-unauthenticated --no-cpu-throttling --cpu-boost --min-instances=1 --max-instances=2`.
- **Failure Domain & Data Residency:** Regional serverless in `europe-west2` (London) for BigQuery, Dataplex, Cloud Run, Vertex AI (`gemini-2.5-flash`), and regional Model Armor (`https://modelarmor.europe-west2.rep.googleapis.com`), paired with EU multi-region Gemini Enterprise (`locations/eu`).
- **RTO / RPO:** **RTO `< 15 minutes`** (stateless container redeployment from source); **RPO `0 hours`** via BigQuery multi-zone storage in `europe-west2` + immutable baseline tables (`students_gold_baseline`, `store_shifts_gold_baseline`) + append-only `change_audit_log` & `portal_change_requests` quarantine resolution (`resolve_quarantined_change`).
- **Data Classification:** Pseudonymous tokenized colleague records (`STU-XXXX`, `SM-XXX`, `age_band` enum) with statutory UK Under-18 working-time constraints (`NFR-02`). Zero raw UK PII permitted.

## 3. Phase 2 Actionable WAF Findings & Remediations (`WAF-01`..`WAF-07`)

| ID | Severity | Pillar | Design Risk / Gap | Concrete Google Cloud Remediation Implemented | Req IDs | Public Documentation Citation |
| :--- | :---: | :--- | :--- | :--- | :--- | :--- |
| **`WAF-01`** | **Critical** | Security | Uploading raw local directories (`.env`, `data/`, `docs/`, `sql/`) into container builds or running as `root` violates least privilege. | Added `.dockerignore` and `.gcloudignore`, split `Dockerfile` (App 2) and `Dockerfile.portal` (App 1), and enforced non-root `USER appuser`. | `NFR-05` | https://docs.cloud.google.com/architecture/framework/security/least-privilege |
| **`WAF-02`** | **High** | Security | Co-locating Student/SM intake UI with HR matching & override endpoints or leaving App 1 unauthenticated exposes internal portals. | Split into two Cloud Run services: `next-portal-intake-app` (App 1 with Cloud Run native `--iap --no-allow-unauthenticated`) and `next-student-transfer-agent` (App 2 with `--no-allow-unauthenticated` and Discovery Engine invoker IAM). | `FR-08`, `NFR-05` | https://docs.cloud.google.com/run/docs/securing/identity-aware-proxy-cloud-run |
| **`WAF-03`** | **High** | Reliability | Writing unvalidated Student/SM self-service edits directly into `students_gold` or `store_shifts_gold` risks corrupting live matching runs. | Implemented Two-Dataset Medallion isolation: App 1 writes to `next_student_transfer_staging.portal_change_requests`; only `100%` valid edits promote (`PROMOTED`) to `next_student_transfer_gold`, while `DQ-01..DQ-06` violations remain `QUARANTINED` until HR resolves via `resolve_quarantined_change(..., confirm=True)`. | `FR-04`, `FR-08` | https://docs.cloud.google.com/bigquery/docs/best-practices-storage |
| **`WAF-04`** | **Medium** | Operational Excellence | Batch-only Dataplex scans have 30–60s startup latency during a live demo, whereas SQL-only views lack native Dataplex Console governance history. | Combined both: App 1 triggers `next-student-transfer-dq-scan:run` asynchronously on `portal_change_requests` while App 2 queries `v_data_quality_warnings` (`0ms`) + latest completed `DataScan` job metadata. | `FR-07`, `FR-08` | https://docs.cloud.google.com/dataplex/docs/auto-data-quality-overview |
| **`WAF-05`** | **Medium** | Reliability | Mid-stream CPU throttling or cold-start delays on Cloud Run App 2 can cause Gemini Enterprise A2A streaming turns to time out. | Deployed `next-student-transfer-agent` with `--no-cpu-throttling --cpu-boost --min-instances=1 --max-instances=2`. | `FR-07`, `NFR-03` | https://docs.cloud.google.com/run/docs/configuring/cpu-allocation |
| **`WAF-06`** | **Medium** | Operational Excellence | Calling `gmail.googleapis.com` directly with Cloud Run ADC fails with HTTP 400 (`Precondition check failed`) without Workspace domain-wide delegation. | Removed `src/workspace_mailer.py`; `hr_comms_and_intervention_agent` stages regex-verified `+` alias emails (`STAGED_FOR_GE_GMAIL`) and outputs copy-clean blocks for a 2-turn handoff to Gemini Enterprise's native `@Gmail` Connector. | `FR-08` | https://docs.cloud.google.com/gemini/enterprise/docs/connectors |
| **`WAF-07`** | **Low** | Security (Accepted Demo Waiver) | Single project compute Service Account used across App 1 & App 2 during PoC showcase. | Documented explicit separation into `sa-portal-intake` and `sa-hr-agent` plus Vertex AI Agent Engine (`europe-west2`) in the NEXT IT Target State (`IT_HANDOVER_BUNDLE/`). | `NFR-05` | https://docs.cloud.google.com/iam/docs/best-practices-for-using-service-accounts |
